# 랭킹 변경 기록

펫별 랭킹(닉네임, 레벨, 공격·방어·순발·내구)을 수집할 때마다 쌓는 기록입니다.

| 파일 | 내용 |
|---|---|
| `snapshots/<날짜_시각>.json` | 그 시점의 전체 랭킹 원본. 수정하지 않습니다. |
| `changes/<날짜_시각>.json` | 직전 스냅샷과 비교한 변경 상세 |
| `changes_index.json` | 변경 기록 목록과 요약 (이벤트 종류별 건수) |
| `timeline.json` | (펫 id → 닉네임)별 레벨·스탯 시계열. 값이 바뀔 때만 한 줄 추가 |

시각은 한국 시간(+09:00)입니다. 파일명 `2026-10-24_1640` = 2026년 10월 24일 16시 40분 수집.

## 변경 이벤트 종류 (`changes/*.json`의 `events[].type`)
- `level_up` : 같은 닉네임의 레벨이 올랐습니다. `delta`(스탯 상승량), `per_level`(레벨당), `expected_by_growth`(성장률로 계산한 기대 상승량)를 함께 기록합니다. 예: 132→133레벨에 공+2 방+3 순+1 내+10.
- `stat_change` : 레벨은 같은데 스탯이 달라졌습니다 (장비·각성 등 가능성).
- `level_down` : 레벨이 내려갔습니다 (환생 등 가능성).
- `rank_move` : 스탯은 같고 순위만 바뀌었습니다.
- `enter` : 새로 순위권(상위 3)에 들어왔습니다.
- `exit` : 순위권에서 빠졌습니다 (밀려났거나 이름·레벨이 바뀌었거나 삭제).

## 알아둘 점
- 같은 펫 안에서 **닉네임으로 동일인을 추정**합니다. 게임에서 닉네임 중복이 가능해서, 동명이인이 있으면 다른 사람으로 보일 수 있습니다.
- 랭킹에 3명까지만 보입니다. 순위권 밖의 변화는 알 수 없습니다. `exit`가 반드시 "랭킹에서 사라짐"을 뜻하지는 않습니다.
- 닉네임을 바꾸면 `exit` + `enter`로 기록됩니다.
- 첫 기준 스냅샷(`2026-10-24_0039`)은 이전 수집본을 git 기록에서 복원한 것이고 시각은 대략값입니다. 두 번째(`2026-10-24_1640`)의 시각도 파일이 도착한 시각 기준입니다.
- `격수`처럼 같은 이름의 펫이 여러 종(id)인 경우, 이벤트가 id마다 따로 기록됩니다.

## 갱신 방법
```
python3 tools/rank_history.py rankings_latest.json --at 2026-10-25T09:00:00+09:00
python3 app/build.py        # 앱에 반영
```
